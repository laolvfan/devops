# ADR-001：耗时任务采用异步 Job

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；A11/B11 配对组约定

## 背景

DRAFT、BuildChecker、EChecker 和 MDFixer 可能执行较长时间。同步等待会让客户端请求依赖构建和分析耗时，也不便查询进度和串联跨服务任务。E2 阶段的目标是约定接口，不要求部署真实 API。

## 决策

- 创建任务后立即返回 HTTP `202` 和服务端生成的 `job_id`。
- 客户端通过 `GET /v1/jobs/{job_id}` 查询任务状态与结果。
- 用 `status` 表示任务状态，用 `execution` 记录执行信息。
- E2 阶段完成接口和样例约定，不要求部署真实 API。

## 备选方案分析

- **同步等待任务完成**：调用路径较直接，但会令 HTTP 请求受任务耗时限制，也无法在执行期间通过独立接口查询状态。
- **各服务自行设计任务创建和查询方式**：单个服务较自由，但跨服务客户端和配对组联调需要处理多套生命周期约定。

## 后果

- 服务需要保存任务状态并提供查询。
- 接口需要定义统一的任务状态和结果格式。
- 任务执行时间与创建请求解耦。
- 当前仓库落实的是接口、Schema 和样例约定；不据此宣称真实 API 已部署。
