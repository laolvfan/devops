# ADR-007：只返回完整且验证通过的正式产物

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；A11/B11 配对组约定

## 背景

失败任务可能已经产生部分 Dockerfile、依赖图或 Patch。若这些结果出现在正常 `output` 中，下游容易把半成品当成可用产物。

## 决策

- 只有任务成功且完成该服务要求的验证时，才返回正式 `output.artifacts`。
- `FAILED`、`TIMED_OUT`、`CANCELLED` 时，`output` 必须为 `null`。
- 中间文件可供内部排错使用，但不作为下游正式输入。
- MDFixer 修复后仍有 MD 时，任务失败，使用 `REPAIR_6001`，不返回正式 Patch。

## 备选方案分析

- **失败时也返回部分产物**：有利于调试和恢复，但消费者必须理解每种产物的有效阶段，误用风险更高。
- **返回产物并添加 `accepted` 标志**：可以保留中间结果，但各消费者都要实现相同的完整性判断。
- **只靠 HTTP 状态表达任务成功或失败**：异步创建和查询时，HTTP 请求本身可能成功而后台任务仍在运行或失败，不能替代 Job 状态。

## 后果

- 下游只需消费成功任务中的正式产物。
- 失败详情通过 `error` 和日志 URI 提供。
- 服务必须在发布正式产物前完成各自契约要求的构建、测试或重检。
- 内部调试产物与正式 artifact 的存储及读取边界需要明确。
