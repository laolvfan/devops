# ADR-009：按服务职责串联实验流程

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；A11/B11 配对组约定

## 背景

实验由 A、B 两组分别负责检测、环境生成和依赖修复，需要明确服务间的交接顺序、责任边界和修复后的验收方式。

## 决策

- B 组 DRAFT 生成可构建环境。
- A 组 BuildChecker 执行全量依赖检测。
- A 组 EChecker 执行跨提交增量检测。
- B 组 MDFixer 根据 MD 报告生成修复 Patch。
- A/B 组协作重新构建、测试和检测，再决定是否接受 Patch。

流程：

```text
DRAFT → BuildChecker → EChecker → MDFixer → 构建、测试、重检
```

## 备选方案分析

- **由单一小组负责所有服务**：责任链较短，但不符合课程中 A/B 组分工和跨组接口练习目标。
- **跳过增量检测，直接把全量报告交给 MDFixer**：流程较短，但失去跨提交变化识别，修复输入不再体现 EChecker 的职责。
- **MDFixer 生成 Patch 后立即接受**：省去协作验收，但无法确认 Patch 能否应用，也不能证明构建、测试和重检通过。

## 后果

- DRAFT 产物需要提供给检测服务。
- A 组的 MD 报告需要与待修复 commit 对齐。
- MDFixer 的 Patch 必须经过重新构建、测试和检测。
- 各阶段通过 Job/artifact 契约交接；本 ADR 约定流程与责任，不声称真实联调已完成。
