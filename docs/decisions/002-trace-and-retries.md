# ADR-002：用 `trace_id` 关联流程，用新 `job_id` 表示重试

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；A11/B11 配对组约定

## 背景

一条实验流程会经过多个服务；任务失败后可能重试。需要分别标识整条流程、单次任务和重试关系，并避免网络重试造成重复创建任务。

## 决策

- 每个 Job 的 `job_id` 全局唯一，由服务端生成。
- 同一流程中的多个 Job 使用相同的 `trace_id`。
- 重试时创建新的 `job_id`，保留原 `trace_id`。
- 用 `retry_of_job_id` 指向上一次任务。
- 创建请求携带 `idempotency_key`，避免重复提交创建多个相同任务。

## 备选方案分析

- **所有任务只用一个 ID**：字段较少，但无法清楚地区分一条流程中的多个服务任务和多次尝试。
- **每次重试生成新的 `trace_id`**：便于单独筛选一次尝试，却切断原实验流程的关联。
- **不使用幂等键**：客户端重试创建请求时可能重复排入相同工作。

## 后果

- 可以按 `trace_id` 查看完整实验流程。
- 可以区分每次执行，并追溯重试关系。
- 服务端需要生成并管理 Job 标识，也需定义幂等键的作用范围和保留期。
