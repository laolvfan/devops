# ADR-004：使用稳定的 `configuration_id` 标识构建环境

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；A11/B11 配对组约定

## 背景

实际依赖图和检测结果依赖构建环境。若 baseline 和当前任务使用不同工具链或构建配置，比较结果可能无效。commit 和 Job 标识描述的是源码版本与任务实例，不能代替环境身份。

## 决策

- 使用以下格式：
  ```text
  cfg-<系统>-<工具链>-<模式>-<版本>
  ```
- 示例：`cfg-ubuntu22-gcc12-release-v1`。
- 任何影响构建结果的环境配置发生变化，都必须生成新的 `configuration_id`。
- `configuration_id` 不包含 commit、`job_id`、`trace_id` 或任务类型。
- EChecker 的 baseline 配置必须与当前任务配置一致，否则拒绝请求。

## 备选方案分析

- **只记录工具链名称**：容易遗漏系统、构建模式或影响结果的版本变化。
- **把 commit 放进配置 ID**：能区分每次输入，但同一环境下不同提交无法复用和比较 baseline。
- **仅在请求里重复完整环境字段、不提供稳定 ID**：字段可读，但跨任务匹配和产物追溯更容易出现字段不一致。

## 后果

- 可以判断依赖图是否来自可比较的构建环境。
- baseline 和当前任务的配置不一致时，不能继续做增量比较。
- 负责构建环境的一方需要维护 ID 命名规则，并在影响构建结果的变更时更新版本。
