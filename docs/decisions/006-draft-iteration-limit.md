# ADR-006：限制 DRAFT 的迭代次数

- 状态：B11 决策草案，待 A11 确认
- 来源：E2 需求与接口契约；B11 约定

## 背景

DRAFT 通过生成、构建和修正 Dockerfile 反复尝试。若没有上限，任务可能持续消耗时间和资源。

## 决策

- `max_iterations` 仅用于 DRAFT。
- 类型为正整数，取值范围为 1 到 50。
- 默认值为 20。
- 达到上限仍未成功时，任务失败，错误码为 `EXEC_4004`。

## 备选方案分析

- **不设迭代上限**：可持续尝试直到成功，但无法限制资源消耗和任务时间。
- **所有任务统一使用相同迭代字段**：表面上简化公共结构，却让没有生成修复循环的任务携带无关配置。
- **固定迭代次数且不允许覆盖**：规则直接，但无法按项目复杂度控制预算。

## 后果

- 调用方可以按项目需要覆盖默认值，但不能超过上限。
- DRAFT 需要记录实际迭代次数。
- 该字段不应被其他服务当作超时时间或执行尝试次数。
