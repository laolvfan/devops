# ADR：先校验报告版本，再验证补丁的实际构建行为

编号：B11-241880100-E11；作者：241880100；状态：采用。

## 问题

报告与源码版本不一致时，依赖结论可能失效；仅检查补丁文本位置也无法证明 Make 会重新编译。E11 需要固定 MD，E12 需要实时增量报告，两种来源必须区分。

## 方案与选择

采用现有编排的版本与内容校验，并以真实增量构建作为扩展测试依据。相比仅检查 diff 或只做 clean build，这能观察头文件变化后是否自动重建，直接覆盖缺失依赖的故障。该 ADR 记录本次沿用的接口约束和新增验证选择，不宣称重写了已有编排。

- 封装字段为 schema_version、kind、commit、status、job_id、trace_id、data 和 artifacts。
- E11-B 使用 fixed-md；E12 的修复输入为本轮 incremental-check。
- 封装 commit 及内部报告 commit 都须匹配 target；不匹配返回 STALE_REPORT，停止生成及应用补丁。
- 使用 artifact URI 与 SHA256 关联报告和补丁来源；共享 API 的 configuration_id 另记录环境配置。
- 只补 MISSING，保留 REDUNDANT，避免扩大修复范围。
- macro 补到依赖变量，mixed 补到目标行；保持既有声明形式。

## 验证与影响

新增测试检查：未修复时旧输出 1；修复后 config.h 触发输出 2；extra.h 再次触发重编译并输出 5。过期测试分别覆盖外层和内部版本不一致，断言不生成补丁、不改源码。原始输入与输出保留独立目录，避免覆盖历史证据。

过期测试仅模拟前置 DRAFT，版本检查使用实际实现；真实镜像构建由独立 E11-B 运行验证。完整测试 21 项通过。API 课程样例的成功不代表 B11 版本已部署。后续 cJSON 跨组验证另核对实际服务和约定实现指纹一致，验证本轮缓存、报告与补丁衔接；选题例外仍单独记录。
